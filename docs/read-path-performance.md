# Read-path measurements

Measured against the hygiene PR (#36) on the same Linux workspace using release
builds, Python 3.12.14, Polars 2.0.0, and PyArrow 26.0.0. The fixture has two million
parameter records, generated by `make_bench ... 2000000 par-only`.

Each scenario opens a fresh reader, with one warmup followed by nine timed runs.
The table reports medians; the filesystem and process-wide restart cache are
warm. These are local microbenchmarks, not cross-platform guarantees.

| Read | Before (ms) | After (ms) |
| --- | ---: | ---: |
| Full, 2M rows | 138.00 | 138.16 |
| First 10 rows | 2.62 | 2.64 |
| Matching first-key filter, 1,000 rows | 4.05 | 4.33 |
| Unknown second-key label, zero rows | 56.39 | 2.65 |
| Empty second-key allowed list, zero rows | 56.97 | 2.73 |
| Unknown second-key label, `threads=4` | 41.72 | 2.78 |

The measured gain is avoiding native decoding (and parallel planning) when any
filter dimension resolves to no UEL indices: about 21x for the serial empty-result
cases. Full, head, and selective nonempty reads show no demonstrated speedup.

Limited serial reads also reserve capacity based on the requested row limit
instead of the entire symbol, and stop at exactly that many accepted records.
Previously the native callback stored one extra row; Polars' `head` trimmed it,
but direct `Reader.read_arrow(n_rows=...)` exposed the extra row. This change
reduces unnecessary allocation and fixes the direct API without claiming a
measured head-read timing gain.

Regression testing additionally found that a cached parallel span wholly inside
one compressed block was mistaken for an empty span. Checkpoint ordering now
includes the decompressed offset, preserving the rows for these filters.

## Reproduce

```sh
cargo run -p gdx --release --example make_bench -- /tmp/bench.gdx 2000000 par-only
python benchmarks/bench_read_paths.py /tmp/bench.gdx
```

Build and install each revision with `maturin develop --release` first. CI also
runs this benchmark and uploads its JSON output. Existing dictionary index
widths are preserved: an experiment removing the intermediate conversion did
not improve full-read timing and was not retained.
