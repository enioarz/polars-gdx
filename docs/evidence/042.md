## Deviations and scope notes

- The frozen fixture is written by the pinned gdxrs core writer, not the
  vendored C library writer: aliases, strict domains, registered acronyms and
  typed special values are not expressible through the legacy `GdxWriter`
  surface. The differential tests read the same fixture through the legacy
  C reader, which exercises core↔legacy interop on every asserted symbol.
  No native format normalization was observed; both backends read all nine
  symbols with equal schemas and equal rows modulo the documented projection
  differences.
- `list_symbols`'s `records` for 0-dimensional symbols reports the public row
  count (the synthesized default row) to match the legacy backend's
  reporting; other symbols report physical stored record counts.
- The gdxrs `read_arrow` accumulates the selected rows into one RecordBatch,
  matching legacy behavior; real cursor-backed streaming batches, batch
  limits and backpressure are task 044. Mode A admits the full UEL dictionary
  under the core's root budget exactly as the legacy backend does; bounded
  mode B (`key_mode="uel_id"`, `resolve_labels`) is task 043.
- Parallel reads are not implemented for the gdxrs backend; an explicit
  `threads > 1` request raises `ValueError` (thread admission is task 046).
- Memory/resource measurements: not measured in this task; the core's
  `OpenOptions` defaults (64 MiB root budget) bound the gdxrs path and the
  capped streaming acceptance is task 047.
- Four-platform runs, packaging and the no-GAMS install path on macOS/Windows
  are task-047 gates; only Linux x86_64 was executed here.

## Review findings on revision dd79a3c and their disposition

1. **[P1] Dictionary allocations bypassed budget admission** — a zero-row
   request against a four-million-label file succeeded at ~775 MiB process
   RSS because the cached `Vec<String>` UEL table and the shared Arrow
   `StringArray` were allocated outside any adapter accounting. Fixed:
   `GdxrsReader` now takes an explicit `dictionary_budget_bytes` (default
   256 MiB, the contract §6 combined adapter envelope) and performs an
   admission pass (label count + label bytes, `Vec<String>` payload plus
   Arrow i32 offsets/validity estimate) **before** any allocation;
   insufficient admission raises a clear `RuntimeError` naming the
   estimate and budget, never a silently changed schema. Regression test:
   `test_dictionary_budget_admission_rejects_before_allocation`; the
   four-million-label scenario was re-verified locally (see below).
2. **[P2] `POLARS_GDX_BACKEND=legacy` produced `DEFAULT_BACKEND=""`** —
   the default was derived from `Reader.__name__.removesuffix("Reader")`,
   which strips the legacy class's whole name. Fixed: `_validate_backend_name`
   returns the validated name itself; `_default_backend` and
   `_reader_class` use it. Regression test:
   `test_default_backend_env_names_resolve_to_themselves`.
3. **[P2] Non-level `value_field` requests failed for
   sets/parameters/aliases** — `read_arrow("C", value_field="marginal")`
   raised "missing value column" while legacy returned zero-valued
   records. Fixed: those kinds store only the level field, so a non-level
   request reads the records and projects zero values for every row,
   preserving the legacy field defaults across all supported fields.
   Regression test (both backends):
   `test_non_level_fields_project_zeros_for_set_parameter_alias`.

Post-fix verification: a locally generated four-million-label file
(63-byte labels, gdxrs writer, 256,000,253 bytes on disk) is rejected by
the default budget before any allocation — the zero-row request that
previously ballooned to ~775 MiB process RSS now raises
`RuntimeError: gdxrs backend: full-dictionary admission of 4000000 labels
needs ~368500004 bytes, exceeding the adapter dictionary budget of
268435456 bytes; raise dictionary_budget_bytes or use the bounded ID mode
(task 043)` with process RSS measured at 47 MiB (import baseline 46 MiB),
via `resource.getrusage` ru_maxrss. The throwaway generator used for this
measurement was not retained; the committed admission regression test
covers the same code path with a budget override.
