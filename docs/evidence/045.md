## Deliverables

- **Projection pushdown** (`scan_batches(columns=...)`): when the caller
  names the needed columns, only those key dimensions are decoded
  (`KeyProjection::Mask`) and the value column is skipped entirely when
  unneeded (`ValueProjection::Mask(0)`); the emitted batches contain
  exactly the needed columns, in declared order, with the same stable
  schemas. The key-filter **selection still applies at the decoder for
  dimensions that are not projected** (verified: filtering `dim_0` while
  projecting only `dim_1`). Unknown projected columns and projections
  leaving nothing readable are rejected clearly. The Python layer unions
  every predicate-referenced column into the requested set, so residual
  predicates always find their required columns until evaluated — Polars
  already includes them in `with_columns`, but the source does not rely
  on that.
- **Predicate pushdown** (unchanged semantics, now asserted against an
  unoptimized reference): conjunctions of `col(key) == "label"` and
  `col(key).is_in([...])` fold into the core selection with exact
  case-sensitive byte matching and are re-applied exactly; everything
  else stays residual. No new predicate forms are claimed.
- **Global accepted-row limits**: a limit is pushed below the predicate
  only when the predicate is fully translatable (proven equivalent: the
  selection is the predicate). With residuals, the source reads
  unlimited, filters per batch and counts accepted rows **globally**
  across batches and partitions (the task-044 `remaining` tracking),
  closing the cursor once satisfied; the final projection applies after.
  No per-batch limit, hidden index build or post-output retry exists in
  this path (the core `index` feature is not used in serial scans; no
  restart index is built).
- **Counters**: the cursor's `scan_statistics()` reports the core's
  `decoded_rows` (which by core contract includes selection-rejected
  rows) so pushed and residual paths are distinguishable.

## Acceptance criteria and their tests (tests/test_m7_task045.py)

- **Optimized vs unoptimized reference**: 12 parametrized plan shapes
  (plain, pushed, residual, mixed, projections, heads, zero limit) are
  compared with `collect(optimizations=QueryOptFlags(predicate_pushdown=False))`
  — exact row, order and schema equality (`test_optimized_matches_unoptimized_reference`).
- **Projection pushdown**: the core decodes only the projected columns
  (1-column batches verified at the cursor level), value-only and
  mixed projections, unknown/empty projections rejected clearly
  (`test_projection_pushdown_reads_only_needed_columns`), and selection
  on unprojected dimensions filters exactly
  (`test_selection_applies_to_unprojected_dimensions`).
- **Sparse/all-rejected filters**: absent labels, empty label lists and
  labels used only in other dimensions yield zero rows with the planned
  schema in both key modes (`test_all_rejected_filters_yield_zero_rows_with_schema`).
- **Matches only in later batches**: a residual whose matches occur only
  in the final 100 of 20,000 records — `head(3)` returns the first three
  accepted rows globally (chunked delivery agrees), equal to the
  unoptimized reference (`test_matches_only_in_later_batches_with_global_head`).
- **Mixed pushed/residual predicates**: pushed key predicates keep exact
  case-sensitive semantics alongside residual value conditions
  (`test_mixed_pushed_and_residual_predicates`).
- **Predicates on projected-away columns**: residuals on columns the plan
  projects away still evaluate (retained until evaluated, then the final
  projection applies) (`test_predicate_on_projected_away_column`).
- **Zero limits**: `head(0)` keeps the schema and decodes nothing
  (`test_zero_limit_reads_nothing`).
- **head(n) across boundaries**: every n up to and across the batch
  boundary, with pushed and residual predicates and chunked delivery
  (`test_head_across_batch_boundaries`).
- **Null/special-value cases**: UNDEF/NA/acronym nulls never satisfy
  ordered comparisons, `is_null` matches exactly those rows, ±inf compare
  exactly, EPS projects to +0.0 satisfying `== 0`
  (`test_null_and_special_value_predicates`).
- **Record order** preserved for pushed, residual, projected and limited
  scans in both key modes (`test_record_order_is_preserved_everywhere`).
- **Mode B** (uel_id) projection, label/ID predicates and limits behave
  identically (`test_mode_b_projection_and_limits`).
- **Counters**: exact decoded/returned row counts for pushed, unfiltered
  and projected scans, using the core's documented decoded-rows semantics
  (selection-rejected rows count as decoded)
  (`test_counters_are_exact_for_pushed_and_residual_paths`).
